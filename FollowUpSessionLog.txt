## §Supabase Evaluation Package

### Background
The current design is local-first (localhost REST + stdio/HTTP MCP, SQLite storage). ADR-002 documents PostgreSQL/Supabase as a first-class upgrade path for storage. However, a separate but related question has emerged: could the MCP server itself be deployed to Supabase (or a Supabase-adjacent platform) to provide a hosted online endpoint accessible to SaaS AI chat platforms?

### Why This Matters
Chat platforms (Claude.ai, GitHub Copilot chat, Zed AI, Cursor) support "remote MCP servers" accessed via HTTP. If ai-memory's MCP server is only reachable at localhost, it cannot be connected to these platforms. A hosted deployment would enable:
- Agent memory persistence across different machines and chat sessions
- Team-shared memory contexts (multi-user scenario)
- Zero-install AI agent integration (no local server required)
- Obsidian-style "brain in the cloud" accessible from any device

### What "Supabase MCP hosting" could mean (three interpretations)
1. **Storage-on-Supabase + MCP server elsewhere:** Supabase provides PostgreSQL + pgvector (storage backend switch from SQLite per ADR-002), while the C#/.NET MCP server is deployed to Azure Container Apps / Fly.io / Render with a public HTTPS endpoint. Supabase = database only.
2. **Supabase Edge Functions as MCP handler:** MCP tool handlers are implemented as Supabase Edge Functions (Deno/TypeScript). This would require a TypeScript rewrite of the MCP facade; Core service logic would need porting or a JSON-over-HTTP bridge to a C# backend.
3. **Supabase Realtime + Row-Level Security:** Use Supabase's built-in auth (JWT/anon keys), RLS policies for multi-user memory isolation, and Realtime for view push notifications. The C# server connects to Supabase PostgreSQL; Supabase handles auth and multi-tenancy.

### Key Evaluation Dimensions
The next session should evaluate this across:

| Dimension | Questions to answer |
|-----------|-------------------|
| **Architecture fit** | Does option 1, 2, or 3 (above) align with ADR-002 (IMemoryStore), ADR-004 (MCP facade over C# service), and ADR-008 (ambient context)? Which requires fewest ADR revisions? |
| **MCP transport compatibility** | Supabase Edge Functions support HTTP. Does the ModelContextProtocol C# SDK's HTTP/StreamableHTTP transport work as a public HTTPS endpoint? What changes are needed for public-internet MCP (auth headers, CORS, rate limiting)? |
| **Authentication** | NFR-L4 says no auth in v1.0 single-user local mode. A hosted MCP server needs auth. Supabase provides anon/JWT keys. How does this interact with per-project memory isolation and WIP-limit-per-profile? What auth model (API key per user, OAuth, Supabase anon key) is lowest friction for chat platform MCP integration? |
| **Cost** | NFR-C2 hard ceiling is €10/month. Supabase free tier: 500 MB database, 1 GB storage, 2 million Edge Function invocations/month. Supabase Pro: $25/month (over NFR-C2 ceiling for cloud-only users). How does this interact with the cost model? Does the ceiling need renegotiation for a hosted deployment profile? |
| **Multi-tenancy** | Hosted MCP = multiple users potentially sharing one server. Current design has no user identity. How would memories be isolated per user? (Options: one Supabase project per user; RLS policies with user_id column on memories; separate schema per user.) |
| **Local-first + hosted hybrid** | Could both exist simultaneously? (Local SQLite for $0/month offline + optional Supabase mirror for online access.) How would sync work? Is this overcomplicated for v1.0? |
| **Chat platform integration mechanics** | How do Claude.ai, GitHub Copilot, and Cursor actually connect to remote MCP servers? What URL/handshake format is required? Does ai-memory's HTTP transport (StreamableHTTP) already satisfy these platform requirements, or are there protocol differences? |
| **Delivery impact** | Would hosted MCP need a new story (ST-021?) and new ADR (ADR-009?)? Would it be additive to Phase 3 (after ST-007) or a Phase 6+ item? |
