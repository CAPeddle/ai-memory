<locked_contract>
**U2 register contract (pre-provisioned bearer — do NOT invent mint/return semantics).**
Per the canonical plan (`docs/plans/...` §U2) and §7.1 of the findings: each node carries its own
per-node bearer in its own env var (the Phase-3 client supplies it). Registration *validates and
upserts*; it returns `node_id`. Registration therefore:
- Reads the presented `Authorization: ****** header, computes `sha256Hex(rawBearer)`.
- Upserts the node keyed by `bearer_token_hash` (UNIQUE), returning the existing-or-new `node_id`.
- Returns `{ "node_id": "<uuid>" }` with HTTP 201. It NEVER returns a raw or minted bearer.

**U2 events contract.** `/workflow/nodes/:node_id/events` bulk-inserts with
`ON CONFLICT (node_id, client_seq) DO NOTHING` and returns an acknowledgement covering every
submitted `client_seq` (both freshly inserted and already-present). The full ownership binding and
auth-rejection edges are hardened in Plan 02; this plan wires the happy path and the duplicate-ack
path.
</locked_contract>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| node → hub (`/workflow/nodes/*`) | Untrusted machine-to-machine request over Tailscale crosses into hub persistence. |
| request → workflow store | User-controlled bearer, node_id, and event payload cross into SQL and the run_events table. |
| optional workflow module → server boot | Presence/absence of a node bearer must not influence whether the server starts. |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | register handler / execution_nodes | high | mitigate | Persist only sha256Hex(bearer); never log Authorization or any raw bearer; return only node_id (Task 3). |
| T-02-04 | Tampering | store.ts SQL under AGE-polluted search_path | high | mitigate | Every table/index/DML is `workflow.`-qualified in 003/004 and store.ts; enforced by workflow-boundary.test.ts schema-qualification test (Task 3). |
| T-02-05 | Denial of Service | events batch / payload size | medium | mitigate | Zod `events` array `.min(1).max(500)`, `event_type` non-empty, `client_seq` int>=0 (Task 3). Payload-size ceiling hardened in Plan 02. |
| T-02-06 | Tampering | duplicate replay of (node_id, client_seq) | medium | mitigate | UNIQUE(node_id, client_seq) + `ON CONFLICT DO NOTHING`; acknowledgement re-derived by SELECT so duplicates are acknowledged, not errored (Tasks 2/3). |
| T-02-07 | Denial of Service | optional-module boot coupling | high | mitigate | Node bearer validated only in the handler/middleware; startupValidation.ts untouched; routes mounted inside workflowBootstrap.enabled (Task 3). Boot-isolation red control in Plan 02. |
| T-02-SC | Tampering | Option B dependency (npm:bcryptjs) | high | mitigate | Only reachable via the Task 1 checkpoint:decision; Option B requires PO approval + deliberate deno.lock refresh + package-legitimacy verification before any install. Option A (default) adds no dependency. |

Cross-node injection (T-02-02) and bearer timing comparison (T-02-03) are high/medium threats whose
rejection paths are owned by Plan 02; this plan's events handler binds writes to the node's own
returned node_id and introduces no cross-node read surface.
