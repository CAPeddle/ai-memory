<locked_contract>
**U2 register contract (pre-provisioned bearer — do NOT invent mint/return semantics).**
Per the canonical plan (`docs/plans/...` §U2) and §7.1 of the findings: each node carries its own
per-node bearer in its own env var (the Phase-3 client supplies it). Registration *validates and
upserts*; it returns `node_id`. Registration therefore:
- Validates the presented `Authorization: Bearer <token>` header matches the required bearer format
  (`^[0-9a-f]{64}$`, see <bearer_input_contract>) and, if not, rejects with 401 before hashing.
- Computes the deterministic `sha256Hex(rawBearer)` (64-char lowercase hex) — the **Option A** design
  confirmed at Task 1.
- Upserts the node keyed by `bearer_token_hash` (UNIQUE), returning the existing-or-new `node_id`.
- Returns `{ "node_id": "<uuid>" }` with HTTP 201. It NEVER returns a raw or minted bearer.

This deterministic single-stored-column upsert is only valid under **Option A**; **Option B** (bcrypt)
is incompatible with a single `bearer_token_hash` column and triggers the schema replan described in
Task 1 (it is out of scope for the execution path below).

**U2 events contract.** `/workflow/nodes/:node_id/events` bulk-inserts with
`ON CONFLICT (node_id, client_seq) DO NOTHING` and returns an acknowledgement covering every
submitted `client_seq` (both freshly inserted and already-present). The full ownership binding and
auth-rejection edges are hardened in Plan 02; this plan wires the happy path and the duplicate-ack
path.
</locked_contract>

<bearer_input_contract>
**Pre-provisioned bearer: entropy & format requirements (Option A execution path).**
The deterministic SHA-256 digest is a sound credential store ONLY because the per-node bearer is a
high-entropy machine secret (at least 128 bits), never a human-chosen password. This plan REQUIRES,
and Task 2 must test, a concrete supported bearer format so the entropy floor is enforceable rather
than assumed:
- **Format:** the raw bearer MUST be exactly 32 random bytes encoded as 64 lowercase hex characters,
  matching `^[0-9a-f]{64}$` (256 bits of entropy — comfortably above the 128-bit floor).
- **Generation (operational, documented):** provision each node bearer with `openssl rand -hex 32`
  (equivalently `python3 -c "import secrets; print(secrets.token_hex(32))"`).
- **Enforcement:** validateNodeBearer / register MUST reject any bearer that does not match
  `^[0-9a-f]{64}$` with 401 BEFORE hashing or persisting — a malformed or short bearer is not a valid
  node credential. This is a format/length floor that guarantees the minimum ENCODED entropy; it is
  NOT a claim that length alone implies randomness (the generation command supplies the randomness).
- Under **Option B** this contract is replaced by the fingerprint+verifier schema and is out of scope
  for this plan.
</bearer_input_contract>
