<objective>
Expand the tracer into a spool that actually survives an outage: bounded, oldest-first, crash-safe,
with a visible drop counter — and a durability proof for the `client_seq` counter that stops criterion 1
from passing on evidence that does not establish it.

Purpose: criteria 2, 3 and 4 are all properties of the spool under failure, and none of them are
observable on the happy path the tracer proved. This plan is also where the phase's most subtle trap is
closed: D-14 records that a client deriving its sequence number from the spool's last line resets to
zero on every successful flush — the steady state, not an edge case — after which a fresh event collides
with an already-acknowledged `client_seq`, the hub's `ON CONFLICT DO NOTHING` discards it, the read-back
ack returns the *old* row, and the client drops the entry believing it was delivered. **Every ROADMAP
success criterion still passes in that failure mode.** The restart test in Task 3 is the only thing that
would notice.

Output: an expanded client and `server/tests/awcp-node-client.test.ts` — in-process, no server, no
database, writing only under `/tmp`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| node client process → local disk (`~/.awcp/`) | Spool and counter state are the only durable record of undelivered events; a torn write here loses events with no upstream copy. |
| unbounded event production → finite node disk | Without a bound, a long outage fills the node's disk and takes the machine, not just the client, down. |
| test process → the runner's real `$HOME` | An in-process test that forgets to inject `config.home` writes into the developer's (or CI's) actual `~/.awcp/`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-03-01 | Denial of Service | unbounded `~/.awcp/spool.jsonl` growth during a long outage | high | mitigate | Task 1 bounds the spool at `AWCP_SPOOL_MAX_ENTRIES` (default 1000 × ≤16 KiB ≈ 16 MiB worst case) and evicts oldest-first, asserted with a cap of 3 and 5 appends. |
| T-03-03-02 | Tampering | a torn `spool.jsonl` or `state.json` from a crash mid-write | high | mitigate | Both files shrink only via the rewrite-and-rename primitive (temp file → `fsyncSync` → `renameSync`, atomic on the same filesystem). Task 1's acceptance criteria include an injected failure between temp-write and rename, asserting the previous file survives byte-identical. |
| T-03-03-03 | Repudiation | events dropped silently, leaving no account of what was lost | high | mitigate | Every drop increments a persisted `dropped_events` total, emits one structured stderr line naming the seq and the reason at the moment it happens, and is readable afterwards via `status`. Three independent surfaces, all asserted. |
| T-03-03-04 | Tampering | silent loss via a `client_seq` that resets on drain | critical | mitigate | Task 3 rebuilds the config from disk after a drain and after deleting the spool entirely, asserting the next seq exceeds the highest delivered one. This is the one failure mode in the phase under which every ROADMAP criterion passes while "exactly once" is false. |
| T-03-03-05 | Information Disclosure | a test writing into the runner's real `~/.awcp/` | medium | mitigate | Every test injects `config.home` from `Deno.makeTempDir()`; the suite is required to pass with no permission flag beyond `--allow-write=/tmp`, so a test escaping to `$HOME` fails on permissions rather than succeeding quietly. |
| T-03-03-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package-manager install occurs; Node built-ins only (D-07). |
</threat_model>
