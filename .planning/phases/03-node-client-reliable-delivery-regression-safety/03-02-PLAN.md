<objective>
Prove the whole architecture with one event. Create `server/scripts/awcp-node-client.mjs` carrying the
thinnest complete path — allocate a `client_seq`, append it to the spool with `fsync`, POST it to a
**real spawned hub process**, read the acknowledgement, remove exactly the acknowledged entry — and a
Deno test that drives that path end to end over real HTTP. Then extend the same test file with the
EVENT-01 duplicate-replay proof.

Purpose: three things in this phase are assumptions rather than facts, and all three are cheapest to
falsify here, on the first commit, rather than after five layers are built on them: (1) that Deno's
`node:` compatibility layer can import a Node `.mjs` under this repo's `frozen`+`strict` settings
(D-09), (2) that the entry-point guard fires correctly under Deno as well as Node (RESEARCH.md
Pitfall 5), and (3) that the client's ack-shape handling matches the hub's real wire types. A tracer
that fails here costs one commit; the same failure discovered in 03-04 costs four.

Output: a production-quality (not prototype) single-path client and the real-HTTP test file that gates
it. Functionality is deliberately incomplete; architecture is not.
</objective>

    `writeSpool` implements RESEARCH.md Pattern 1: write the full new line set to a temp file in the
    same directory, `fsyncSync` it, `closeSync`, then `renameSync` over the target. `rename` is atomic
    on the same POSIX filesystem, so a crash mid-write leaves either the old complete spool or the new
    one — never a truncated one. A plain `writeSync` without `fsyncSync` is not sufficient: a
    synchronous Node write blocks the event loop but does not force the OS page cache to disk.

    persisted node_id does not yet exist and the secret is present in the environment**. It persists
    only the returned `node_id` to `<home>/node_id` at mode `0600` — never the secret, never the bearer
    (D-12, D-13). Fail fast with a clear local message if `bearer` does not match `BEARER_FORMAT`,
    before spending a round trip; the hub remains the authority.

    `flushOnce` POSTs `{events: batch}` to `<hubUrl>/workflow/nodes/<node_id>/events` and returns
    `{outcome: "acked", acked: number[]}` on 200, where `acked` is
    `body.acknowledged.map((a) => a.client_seq)` — read the unwrapped `client_seq` field, and treat it
    as a JS number. Comparing spool entries against the raw array elements, or against a stringified
    value, is the client-side half of the defect `store.ts:840-846` documents having already fixed
    server-side: the entries would never clear and would be retried forever. For any non-200, throw a
    typed error carrying the status — 03-04 replaces the throw with real branches.

    `flush` reads the spool oldest-first, takes at most `FLUSH_MAX_EVENTS`, calls `flushOnce`, and on
    an `acked` outcome rewrites the spool to exactly the entries whose `client_seq` is NOT in `acked`.
    Removal happens only here, only after a 200 that named the seq. Nothing removes an entry on send or
    on retry attempt (EVENT-03).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| node client process → hub HTTP surface | The client transmits a raw 64-hex bearer, and on first registration an operator enrolment secret, across the network. On z2 this link is tailnet/WireGuard-encrypted; in tests it is loopback. |
| node client process → local filesystem (`~/.awcp/`) | Credentials must not land here; `node_id` and spool state must not be world-readable. |
| test process → shared `db-test` database | Rows written by a spawned hub outlive the test unless cleaned up, and `db-test` accumulates across runs. |
