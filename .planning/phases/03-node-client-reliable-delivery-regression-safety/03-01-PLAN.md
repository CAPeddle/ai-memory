<open_questions>
**Does `FEATURE_WORKFLOW` stay enabled on the base `mcp` service after Phase 3 ends?**

D-01 requires it enabled *for* this phase and rates the change reversible. It does not say what happens
afterwards. Leaving it on permanently changes the maintainer's day-to-day dev surface: `/api/workflow/*`
and an **unauthenticated `/workflow` dashboard shell** become part of every `docker compose up -d`, on a
port published on all interfaces. Turning it off afterwards restores today's behaviour but re-breaks any
future real-node work without warning (404, not 401).

This is a maintainer decision, not an executor one. Record it in the phase findings either way; do not
silently pick. See `<threat_model>` row T-03-01-02.
</open_questions>
