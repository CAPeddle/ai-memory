<objective>
Make failure terminate. Add the two non-200 branches the tracer deliberately left as a throw — a
permanent rejection that drops exactly what the hub named, and an authentication failure that stops —
plus bounded backoff, the heartbeat/checkpoint reporting the Phase Boundary puts in scope, and the
repeatable gate that proves no credential reaches the client's output.

Purpose: three of this phase's failure modes are livelocks rather than crashes, and a livelock presents
as a hub bug. A single oversized event 400s the whole batch, nothing is acked, ack-before-drop forbids
dropping, and the client retries forever — that is experiment 4's most likely wrong ending. A permanent
401 never clears the spool either, so the naive client hammers a hub published on `0.0.0.0:3000` while
filling both the spool and the transcript being captured as evidence. And D-13 is, without this plan,
the only decision in `03-CONTEXT.md` that is asserted and unchecked — the kind that gets discovered
after publication, in git history.

Output: a client that reaches a stated terminal state on every failure path it can encounter, reports
liveness, and cannot leak.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| node client → hub, on the failure paths | The failure paths are where a client hammers, leaks, or livelocks; the happy path is not where any of this goes wrong. |
| client process output → captured transcript → git history | This phase deliberately captures stdout/stderr as evidence and quotes it into a committed findings document, so anything printed is a publication. |
| client process → hub published on `0.0.0.0:3000` | An unbounded retry loop from a node is a denial-of-service against the maintainer's own dev host. |
