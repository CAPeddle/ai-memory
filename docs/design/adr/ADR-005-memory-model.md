# ADR-005: Memory Model and Tier Architecture

**Status:** Revised  
**Date:** 2026-05-15 | **Revised:** 2026-05-16  
**Deciders:** PO (sole maintainer)  
**Source investigations:** [memory-architecture-design.md](../../investigations/memory-architecture-design.md), [openbrain-pivot-evaluation.md](../../investigations/openbrain-pivot-evaluation.md)

---

## Context

The original memory model was defined against a custom SQLite schema. The base is now a fork of OB1, which uses a single flat `thoughts` table in PostgreSQL. The tier model (Shards / Wiki) must be expressed on top of OB1's base schema rather than as a ground-up custom design.

Additionally, PostgreSQL + AGE (`PG15/v1.6.0-rc0`, see ADR-011) is now available, which enables the entity graph layer to use openCypher rather than SQLite recursive CTEs or structural fingerprint workarounds.

The conceptual tier model is unchanged — Shards (episodic, raw) and Wiki (semantic, promoted) remain the two memory types. The mechanism for expressing this distinction on OB1's schema is a spike deliverable (ST-021).

---

## Decision

### Three-tier conceptual model (unchanged)

```
TIER 1: SHARDS (Episodic Memories)
  → Raw, faithful capture of observations
  → No write-time curation or judgement
  → Source: user input, agent observations, session logs

TIER 2: WIKI (Semantic Memories)
  → Promoted, curated, evergreen facts
  → Transition: Consolidation Pipeline (ADR-007) promotes Shards → Wiki
  → Source: user-taught facts, auto-promoted via consolidation scoring

VIEWS (Local Projections — generated by synthesis service, not stored in cloud)
  → Wiki View:   synthesis of Tier 2 per project → Obsidian Markdown
  → Storyboard:  stateful task board → Obsidian Markdown + MCP tools
```

### Base schema — OB1's `thoughts` table

The fork builds on OB1's core table. The tier distinction is added via a `memory_type` column. The exact schema extension mechanism (single table with discriminator vs separate tables) is a deliverable of spike ST-021.

OB1 base (inherited):
```sql
CREATE TABLE thoughts (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  content     text NOT NULL,
  embedding   vector(512),          -- 512-dim (ADR-003)
  metadata    jsonb DEFAULT '{}'::jsonb,
  content_fingerprint text,         -- deduplication hash
  created_at  timestamptz DEFAULT now(),
  updated_at  timestamptz DEFAULT now()
);
```

Planned additions (to be validated in ST-021):
- `memory_type`: `shard` | `wiki` — tier discriminator
- `project`: text — project slug for scoping and boosting
- `profile`: text — `professional` | `personal`
- `active`: boolean — soft-delete flag
- `supersedes`: uuid — correction pointer (null for original records)
- `recall_count`: integer — frequency signal for consolidation
- `last_recalled_at`: timestamptz
- `source`: text — `user-taught` | `auto-promoted` | `observed`
- `confidence`: float — consolidation score at promotion time (wiki only)
- `search_vector`: tsvector — generated column for BM25 search

### Entity graph — AGE / openCypher

The entity and relationship graph is stored natively in AGE within the same PostgreSQL database. Entities and edges are populated by the entity extraction worker (ADR-007).

```cypher
-- Entities (nodes)
CREATE (:Person {name: 'John', slug: 'john'})
CREATE (:Topic {name: 'flowers', category: 'nature'})
CREATE (:Function {name: 'processPayment', file: 'billing.ts'})

-- Relationships (edges)
MATCH (a:Person {slug:'john'}), (b:Topic {name:'flowers'})
CREATE (a)-[:LIKES]->(b)

-- Thought ↔ entity links (hybrid relational + graph)
```

Thought-to-entity linking uses a join table (`thought_entities`) in the relational schema, consistent with OB1's `entity-extraction` schema pattern.

### Memory never decays (unchanged)

All memories retain full weight regardless of age. Recency is used only as a tiebreaker (within ε=0.01 score threshold).

### Identifier strategy — UUID

OB1 uses PostgreSQL `gen_random_uuid()` (UUID v4). ULID is dropped in favour of UUID to remain consistent with the OB1 base schema and avoid a custom generator dependency.

Trade-off: UUIDs are not time-sortable. Chronological ordering uses `created_at` (indexed timestamptz column), which achieves the same result.

### Soft-delete and corrections model (unchanged)

- Deletion: `active = false` flag; excluded from search but preserved for audit
- Correction: new record with `supersedes` pointing to old UUID; old record soft-deleted. Full correction history preserved.

## Consequences

### Positive
- OB1's base schema is production-validated; the fork inherits its deduplication, upsert, and embedding patterns
- Single PostgreSQL database hosts relational memories, pgvector embeddings, tsvector indexes, and the AGE graph — no external graph store required
- AGE enables openCypher for entity traversal; the graph layer is now first-class rather than a future migration target
- UUID PKs align with OB1 and PostgreSQL defaults; no custom ULID generator needed

### Negative / Trade-offs
- UUIDs are not lexicographically time-sortable; chronological queries must use `created_at`. Indexed timestamptz is equivalent in practice.
- The `memory_type` discriminator approach (single table) vs separate tables trade-off is unresolved until ST-021 validates it against the consolidation and search pipelines
- The entity extraction worker must populate the AGE graph before graph queries return results; graph layer has a cold-start period on fresh deployments

## Alternatives Considered

| Alternative | Why Not Chosen |
|-------------|---------------|
| **Custom ground-up SQLite schema (original design)** | Superseded by OB1 fork adoption and PostgreSQL move (ADR-011) |
| **Separate `shards` and `wiki` tables (original design)** | Spike ST-021 will validate whether single-table discriminator or separate tables is cleaner on PostgreSQL; not decided upfront |
| **ULID primary keys** | OB1 uses UUID; aligning with the base avoids a custom generator and schema divergence |
| **Separate graph database (Neo4j, FalkorDB)** | AGE in the same PostgreSQL instance provides openCypher without a second service; simpler ops |
| **Temporal decay model** | Explicitly rejected: development knowledge does not expire; recency as tiebreaker captures needed nuance |
| **Structural fingerprint vectors only (no AGE)** | Covers similarity queries but not multi-hop traversal; openCypher is required for fact inference and debugging use cases (confirmed in architecture review) |
