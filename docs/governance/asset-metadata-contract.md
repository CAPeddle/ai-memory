# Governance Asset Metadata Contract

## Purpose

This contract defines how AI-governance assets are described, cataloged, and validated in this repository.
It standardizes metadata so tooling can discover assets, generate inventories, and detect drift.

## In-Scope Asset Types

Current in-scope categories:
- prompt
- instruction
- skill

Each in-scope asset is represented by file-level frontmatter and catalog entries generated by the governance catalog tooling.

## Reserved Future Categories

Reserved categories for future expansion:
- agent
- hook
- workflow
- plugin

Reserved categories must appear in catalog metadata and documentation even when there are no concrete files yet.

## Required Metadata Fields

Each governed asset must provide the following fields:

| Field | Type | Notes |
|---|---|---|
| name | string | Human-readable title |
| summary | string | One-line purpose |
| asset_type | string | Must be one of prompt, instruction, skill |
| status | string | Current lifecycle state (for example: active) |
| owners | array of string | At least one owner |
| source_path | string | Repository-relative path to source file |

## Optional Fields

Optional metadata fields may be used when available:

| Field | Type | Notes |
|---|---|---|
| tags | array of string | Search and grouping keywords |
| related_assets | array of string | Related asset identifiers or paths |
| notes | string | Maintainer notes |
| last_reviewed | string | ISO date for governance review |

## Generation Rules

1. The canonical source metadata is .github/planning/assets/asset-catalog-source.json.
2. Generated outputs are:
   - .github/planning/assets/asset-catalog.json
   - .github/planning/assets/asset-catalog.md
3. Generated JSON and Markdown must be produced from the same generation flow.
4. Manual edits to generated outputs are treated as drift and must fail validation.
5. Validation is local-command only for ST-012 and must not depend on CI enforcement.
